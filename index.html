📱 1. Fundamentos de Computación Móvil

Unidad 1 • Móviles
  • Clasificación de Dispositivos:
    • Embebido: Interno, inamovible y autónomo (frenos ABS de un auto).
    • Montado: Integrado parcialmente a un anfitrión del que depende (Android Auto).
    • Portátil acompañado: Teléfonos smartphones y tablets personales.
    • Fijo: Estaciones y PCs conectadas a red cableada.
  • Desafíos Móviles: Ubicuidad, autonomía de batería, procesadores térmicamente limitados y conectividad intermitente/discontinua.
  • Optimización con 8 GB RAM: La recomendación técnica del curso es conectar un dispositivo físico real por USB con depuración habilitada en lugar de emular en Android Studio.
Embebido Montado 8 GB RAM USB Debug

🏗️ 2. Anatomía de un Proyecto Android

Unidad 1 • Estructura
  • AndroidManifest.xml: El archivo de registro del sistema. Declara obligatoriamente las Activities, permisos (<uses-permission>), servicios y el intent-filter (MAIN/LAUNCHER) de la pantalla de inicio.
  • Estructura res/ (Recursos):
    • layout/: Archivos XML con el diseño visual de las vistas.
    • values/strings.xml: Textos centralizados para mantenimiento e internacionalización.
    • values/colors.xml y themes.xml: Paletas y estilos.
    • drawable/: Vectores e imágenes gráficas.
    • mipmap/: Íconos de aplicación adaptativos para diversas densidades.
  • Gradle (build.gradle.kts):
    • compileSdk: Versión del SDK usada para compilar.
    • minSdk: Versión mínima de Android requerida para instalar la app.
    • targetSdk: Versión con la que fue testeada y optimizada la app.
AndroidManifest res/ Gradle minSdk / targetSdk

☕ 3. Kotlin: Fundamentos & Null Safety

Unidad 1 • Kotlin
  • Inmutabilidad: val define variables de solo lectura (inmutables, preferidas por seguridad); var define variables mutables.
  • Inferencia de Tipos y Templates: Infiere tipos automáticamente y permite interpolación directa: "Puntos: $score" o "${user.name}".
  • Null Safety (Seguridad ante Nulos):
    • Por defecto los tipos son no-nulos (val s: String = null da error de compilación).
    • Tipos anulables con signo ?: val s: String? = null.
    • Safe Call (?.): Ejecuta si no es nulo, o devuelve null sin arrojar excepción.
    • Operador Elvis (?:): Provee un valor por defecto si la izquierda es nula: val largo = s?.length ?: 0.
    • Not-Null Assertion (!!): Fuerza la desreferencia; si es nulo arroja NullPointerException.
val / var Null Safety Safe Call ?. Elvis ?: !!

🧬 4. POO, Métodos y Herencia

Unidad 1 • POO
  • Clases Final por Defecto: En Kotlin todas las clases son cerradas (final). No se puede heredar de ellas salvo que se declare explícitamente el modificador open.
  • Herencia Sintáctica: La subclase hereda mediante dos puntos: open class Planta() ➔ class Suculenta : Planta().
  • Sobrescritura: Métodos a sobrescribir deben ser open en el padre y llevar override en el hijo.
  • Modificadores de Visibilidad:
    • private: Accesible únicamente en la clase o archivo donde se define.
    • protected: Accesible en la clase y en sus subclases derivadas (herencia).
    • internal: Visible en cualquier parte dentro del mismo módulo.
    • public (por defecto): Visible globalmente.
open / final override protected internal

🏛️ 5. Arquitectura del SO Android (Stack de 5 Capas)

Unidad 1 • Stack SO
  • 1. Linux Kernel: Capa inferior. Maneja drivers (pantalla, cámara, audio, WiFi, Bluetooth), gestión de procesos, memoria física, hilos y seguridad.
  • 2. HAL (Hardware Abstraction Layer): Módulos C/C++ que estandarizan el acceso al hardware físico sin importar el fabricante del microchip.
  • 3. Runtime (ART) & Librerías Nativas:
    • ART (Android Runtime): Reemplazó a Dalvik. Compila bytecode DEX usando AOT (*Ahead-Of-Time*) y JIT (*Just-In-Time*), optimizando el uso de batería y CPU.
    • Librerías Nativas C/C++: SQLite, WebKit, OpenGL ES, SSL.
  • 4. Java API Framework: Herramientas para programadores: ActivityManager, WindowManager, ContentProviders, ViewSystem, NotificationManager.
  • 5. System Apps & User Apps: Aplicaciones preinstaladas del sistema (Contactos, Marcador) y aplicaciones de usuario (como tu app DAM).
Linux Kernel HAL ART (AOT+JIT) Java API System Apps

📦 6. Tipos de Clases en Kotlin

Unidad 1 • Clases
  • data class: Para contener datos. El compilador autogenera equals(), hashCode(), toString(), copy() y desestructuración. Ejemplo: modelos JSON.
  • sealed class: Jerarquías cerradas y finitas en tiempo de compilación. Esenciales en Android para modelar estados seguros de UI (Loading, Success, Error), logrando que el when sea exhaustivo sin requerir else.
  • enum class: Conjunto finito de constantes fijas (ej. enum class Dificultad { FACIL, MEDIO, DIFICIL }).
  • abstract class: Molde que no puede instanciarse; define métodos abstractos a implementar por las subclases.
  • interface: Contratos de métodos y propiedades que pueden contener implementaciones por defecto.
  • object / companion object: object define un Singleton nativo. companion object dentro de una clase aloja miembros estáticos (reemplazo del static de Java).
data class sealed class enum class companion object

🎨 7. UX/UI: Prototipado, Flujos y Nielsen

Unidad 2 • UX/UI
  • Por qué Prototipar y Testear: Permite iterar y validar con usuarios reales antes de programar, reduciendo costos y evitando retrabajos.
  • Escala de Fidelidad:
    • Boceto (Sketch): Papel y lápiz, baja fidelidad, lluvia de ideas rápida.
    • Wireframe: Estructura esquemática en escala de grises. Define disposición y jerarquía sin diseño visual ni fotos.
    • Mockup: Representación estática de media/alta fidelidad con paleta de color, tipografía y estilo visual final.
    • Prototipo: Modelo dinámico interactivo y navegable para simular flujos de usuario reales.
  • Flujos entre Pantallas (User/Screen Flow): Diagramas que mapean la ruta completa del usuario para cumplir un objetivo (Login ➔ Menú ➔ Pregunta ➔ Victoria), identificando puntos de decisión y errores.
  • Leyes de Nielsen (10 Heurísticas): Visibilidad del estado del sistema (feedback), correspondencia con el mundo real, control y libertad del usuario (deshacer/cancelar), consistencia y estándares, prevención de errores, reconocimiento antes que recuerdo.
  • Ergonomía: Ley de Hick (dividir formularios largos), Ley de Fitts y Zona del Pulgar.

🔄 8. Ciclo de Vida de Activity y Fragment

Unidad 3 • Ciclo de Vida
  • Estados: onCreate() (creación/inflado) ➔ onStart() (visible sin foco) ➔ onResume() (interactivo con foco pleno) ➔ onPause() (pérdida de foco) ➔ onStop() (oculta en segundo plano) ➔ onDestroy() (destrucción).
  • Dato Clave de Examen sobre onPause(): Al entrar una llamada o salir de la app, onPause() es el último momento seguro garantizado para persistir borradores, porque ante escasez crítica de RAM el SO puede matar el proceso sin pasar por onStop() ni onDestroy().
  • Fragment: Porción modular de UI con ciclo de vida autónomo acoplado a la Activity huésped.
onCreate() onPause() (Llamada) RAM Kill Fragment

🧠 9. Arquitectura MVVM y Concurrencia

Unidad 3 • MVVM & Hilos
  • Separación de Capas:
    • Vista (Activity / Compose): Dibuja la UI y recibe toques. No procesa lógica pesada.
    • ViewModel: Retiene el estado en memoria RAM. Sobrevive intacto a la rotación de pantalla (evita perder puntajes cuando la Activity se recrea).
    • Repositorio / Modelo: Acceso a datos locales o remotos.
  • Hilo Principal (Main Thread): Atiende exclusivamente el dibujo e interacción. Tareas pesadas provocan el error ANR (Application Not Responding).
  • Corrutinas: Hilos ligeros que corren en segundo plano (Dispatchers.IO) para temporizadores, música o almacenamiento sin bloquear la vista.
ViewModel Rotación ANR Coroutines IO

💾 10. Persistencia de Datos

Unidad 3 • Almacenamiento
  • SharedPreferences: Almacenamiento liviano en formato clave-valor (guarda internamente un XML privado). Ideal para configuraciones simples y flags de estado (ej: isDarkMode = true, volumen, sesión iniciada).
  • Archivos JSON Locales: Almacenamiento estructurado en disco para colecciones de datos moderadas (ej. banco de preguntas del juego, historial de partidas).
  • Confirmación Oficial: La librería ORM Room NO entra en este parcial (queda para la segunda mitad de la materia).
